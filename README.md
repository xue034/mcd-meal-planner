# 麦麦营养配餐助手 · mcd-meal-planner

> 按热量和蛋白目标，从麦当劳真实菜单里算出**带精确数字**的套餐。
> 不是"推荐巨无霸"，而是"巨无霸 513 kcal，蛋白 27g，距你的 800 大卡目标还差 87 kcal，加一份雪菜脆笋鸡肉粥（120 kcal）刚好命中"。

基于麦当劳中国 MCP Server 真实返回的营养数据构建，为减脂期、增肌期、控钠控糖场景提供可验证的配餐方案，并补充当日可用优惠券。

---

## 为什么做这个

市面上的"AI 帮你点麦当劳"给出的建议大多是这样的：

> "推荐巨无霸搭配中薯，可乐换成无糖更健康。"

问题在于——**没有数字**。用户知道自己要控制热量，但得不到「这个组合多少大卡」「距目标差多少」「怎么调整最省事」。

本项目把麦当劳 MCP 接口返回的 **160 条真实营养数据**（能量/蛋白质/脂肪/碳水/钠/钙）建成可计算的数据集，给出精确到克的方案与差值，并明确告知与目标的差距和调整路径。

## 核心特性

| 特性 | 说明 |
|---|---|
| 🎯 精确配餐 | 输入热量/蛋白目标，输出精确到克的组合，附与目标的差值 |
| 🔄 调整建议 | 没命中目标时，直接告诉你"换哪个单品能省多少 kcal" |
| 🧂 钠提醒 | 超建议上限主动警示，推荐 0 卡饮品替换 |
| 🎟️ 今日券叠加 | 补充当天可领优惠券，与配餐方案一并输出 |
|📅 活动同步 | 可查当月活动日历，新品不遗漏 |
| 🔌 离线可跑 | MCP 不可用时回退本地数据快照，核心功能不中断 |

## 使用示例

### 示例 1：减脂期晚餐

**输入**：
```bash
python planner.py --kcal 800 --protein 30 --limit 2
```

**实际输出**（真实运行结果）：
```

数据源：MCP list-nutrition-foods（共 75 条餐品，本地快照）

【方案 1】
====================================================
推荐套餐
====================================================
  · 巨无霸513 kcal | 蛋白 27g | 脂肪 26g | 碳水 42g
  · 雪菜脆笋鸡肉粥    120 kcal | 蛋白  4g | 脂肪  2g | 碳水 22g
  · 卡布奇诺中杯     167 kcal | 蛋白  9g | 脂肪  7g | 碳水 15g
----------------------------------------------------

  钠 1601 mg | 钙 470 mg
----------------------------------------------------

  蛋白：达标（超出 10g）
  钠：1601 mg（占建议上限 80%）
====================================================
```

**方案 2**（同目标，换口味）：板烧鸡腿堡 391 + 小薯条 210 + 冰燕麦奶中杯 199 = 800 kcal / 蛋白 30g / 钠 1306 mg。热量同样精确命中，钠更低，口感更清爽。

### 示例 2：低热量目标

```bash
python planner.py --kcal 500 --limit 1
```
→ 麦辣鸡腿汉堡 485 + 小杯鲜萃咖啡 15 = **500 kcal**，偏差 0。

### 示例 3：忌口/ 排除品类

```bash
python planner.py --kcal 700 --protein 25 --exclude burger --limit 1
```
→ 排除汉堡后自动改用早餐品类：猪柳蛋麦满分 387 + 脆薯饼 146 + 卡布奇诺中杯 167 = **700 kcal / 蛋白 33g**。

### 示例 4：程序化调用

```bash
python planner.py --kcal 800 --protein 30 --limit 1 --json
```
输出结构化 JSON，含每件餐品与合计的完整营养数据，便于集成到其他应用。

## 安装方法

### 方式一：作为 WorkBuddy Skill 使用（推荐）

1. 将本项目克隆到 `~/.workbuddy/skills/mcd-meal-planner/`
2. 重启 WorkBuddy
3. 直接提问即可，助手会自动加载 `SKILL.md` 中的流程

### 方式二：独立命令行使用

```bash
git clone https://github.com/<your-account>/mcd-meal-planner.git
cd mcd-meal-planner
python planner.py --kcal 800 --protein 30
```

**环境要求**：Python 3.10+，无第三方依赖（仅用标准库）。

### 接入麦当劳 MCP（可选，用于获取实时券与活动）

1. 访问 [麦当劳开放平台 MCP 页面](https://open.mcd.cn/mcp)，右上角【登录】→ 手机号验证码
2. 登录后点【控制台】→ 点【激活】→ 同意服务协议 → 复制 MCP Token
3. 设置环境变量：
   ```bash
   export MCD_MCP_TOKEN="你的Token"
   ```
4. 参考 `mcp-config.example.json` 配置你的 MCP Client

> ⚠️ **安全提示**：配置文件只使用环境变量占位符 `${MCD_MCP_TOKEN}`，请勿把真实 Token 提交到版本库。

## 使用示例参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `--kcal` | int | 热量目标（千卡），必填 |
| `--protein` | int | 蛋白目标（克），可选 |
| `--sodium-limit` | int | 钠摄入上限（毫克），默认 2000 |
| `--allow-dessert` | flag | 允许包含甜品，默认排除 |
| `--exclude` | list | 排除品类，如 `burger dessert chicken` |
| `--limit` | int | 返回方案数量，默认 3 |
| `--json` | flag | JSON 格式输出 |

**支持的品类标识**：`burger`（汉堡）、`chicken`（鸡类小食）、`sides`（配餐/小食）、`dessert`（甜品）、`drink`（饮品）、`coffee`（咖啡）、`breakfast`（早餐）、`kids`（儿童餐）

## 计算逻辑说明

引擎采用「候选枚举 + 多维打分」策略：

1. **候选枚举**：遍历主食 × 配餐 × 饮品的所有组合
2. **热量剪枝**：组合总热量超过目标 1.5 倍的直接丢弃
3. **配餐约束**：配餐热量不超过剩余额度 + 150 kcal 容差
4. **多维打分**：
   - 热量偏离度× 1.0（权重最高）
   - 蛋白缺口 × 8.0（按蛋白等价热量计入）
   - 钠超限量× 0.5（超限重罚）
   - 组合完整性罚分 20.0（鼓励完整搭配）
5. **去重**：同一主餐只保留最优组合，避免三个方案口味雷同

## 数据来源与准确性

- 全部营养数值来自**麦当劳中国 MCP Server `list-nutrition-foods` 接口真实返回**
- 采集时间：`2026-10-09T15:17:11+08:00`，接口共返回 160 条
- 本项目收录其中 **75 条常用单品**（覆盖汉堡、早餐、配餐、饮品、咖啡、甜品、儿童餐 8 个品类）
- 原始返回为 TOON（Token-Oriented Object Notation）格式，已转换为标准 JSON

**准确性声明**：营养数据为接口快照，麦当劳菜品会随季节和区域调整，**实际营养成分以麦当劳官方渠道实时数据为准**。本项目不保证与实际出品完全一致。

## 目标用户

| 用户 | 典型诉求 |
|---|---|
| 减脂期人群 | 「500 大卡以内吃什么」——需要精确热量而非模糊建议 |
| 增肌人群 | 「30g 蛋白怎么凑」——需要蛋白数达标的组合 |
| 控钠/控压人群 | 「高血压能怎么点」——需要钠含量可见、可替换 |
| 家庭用户 | 「带孩子吃什么」——儿童餐低热量选择 |
| 健身 + 餐饮爱好者 | 需要可导出的 JSON 数据做饮食记录 |

## 已知局限

1. **不支持门店定位**——`query-nearby-stores` 接口依赖用户收藏门店，对未收藏用户不可用，因此本项目不做「就近门店有什么券」的查询；优惠券信息直接来自用户账户
2. **营养数据为快照**——菜品会更新，请以官方实时数据为准
3. **钠上限 2000mg** 依据一般成人膳食建议值，高血压、肾病患者请遵医嘱
4. **不可做医疗建议**——本项目输出的所有内容仅供参考
